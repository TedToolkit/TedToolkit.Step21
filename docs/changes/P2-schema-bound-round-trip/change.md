## 🎯 Change goal

> When this change is complete, a .NET consumer can supply an EXPRESS schema, read or construct a schema-bound strongly typed model, navigate relationships as ordinary generated entity properties, and write the model as an ISO 10303-21 exchange structure, proven by deterministic generated-code compilation and semantic read-write-read conformance cases.

## 🎯 Intended outcome and scope

The delivery adds a public schema-neutral exchange-structure model and writer, an EXPRESS semantic compiler, an incremental generator, mutable generated entity classes, generated schema metadata and direct generated validation, a schema-bound editable model, typed entity-reference resolution, and diagnostics sufficient for structural ISO 10303-21 data-section mapping.

In scope:

- complete ISO 10303-21 Edition 3 clear-text syntactic recognition, an internal immutable syntax representation of recognized standard constructs, and canonical public writing for the constructs in the declared writer capability set;
- complete ISO 10303-11:2004 EXPRESS syntactic recognition and source-located immutable IR, while executable semantics are delivered in explicitly declared stages;
- executable evaluation of every EXPRESS constraint, expression, query, constant, and function reachable from schema validation or ISO 10303-21 writing by final change completion;
- schema-bound reading, validation, and writing across one or more data sections, with each section governed by its ISO-declared generated schema descriptor and standard population/cross-schema rules applied;
- all `.exp` AdditionalFiles in one compilation as a closed schema set, including multiple schema declarations and deterministic in-set resolution of `USE FROM` and `REFERENCE FROM`, plus the structural declarations needed for entities, inheritance, defined types, enumerations, selects, aggregates, optionality, and physical attribute mapping;
- one interface and one mutable class per EXPRESS entity, with all schema inheritance expressed by interfaces and every generated entity class inheriting only `Entity`;
- schema-neutral scalar and physical-parameter values for INTEGER, REAL/NUMBER, STRING, BINARY, BOOLEAN, three-state LOGICAL, enumeration, typed/untyped parameters, OPTIONAL absence `$`, and derived marker `*`;
- exchange-structure-owned `EntityInstanceName` serialization identity, deterministic section-aware graph Add, non-cascading Remove, direct mutable generated entity properties, two-phase forward/cyclic reference hydration, unchecked editing, boundary validation, and deterministic identity-based writing;
- a generated live, one-level `DirectReferences` view on every entity that enumerates physically written entity-reference occurrences without reflection, plus cycle-safe transitive registration by `ExchangeStructure.Add`;
- simple and complex entity instance mappings supported by the implemented EXPRESS subset;
- source-located parser, schema, binding, resolution, and writer diagnostics;
- exact statically dispatched public descriptor/read/write contracts and dedicated syntax, binding, read-validation, write-validation, and unsupported-capability exceptions carrying complete diagnostics or validation results;
- direct generated validation and aggregate results that identify every detected failure through a stable code, deterministic string path, message, and available constraint source location in a reference-identity-safe traversal;
- generated schema-constraint metadata and equivalent XML documentation derived from the same EXPRESS IR as executable validation rules;
- mutable schema-neutral `ExpressArray<T>`, `ExpressList<T>`, `ExpressBag<T>`, and `ExpressSet<T>` runtime types that retain aggregate kind and editing state until boundary validation;
- internal ANTLR visitors that transform Part 21 parse trees to internal `ExchangeStructureSyntax` and EXPRESS parse trees to immutable schema IR, with listeners suppressed;
- deterministic source composition through TedToolkit.RoslynHelper;
- semantic round-trip verification against repository fixtures and independently pinned corpora.

Non-goals for this change:

- JSON, XML, ORM, database, or general object serialization and related extension points;
- domain-specific STEP application protocol, IFC, CAD, or BIM APIs;
- byte-for-byte preservation of comments, whitespace, line wrapping, leading-zero spelling, or source ordering;
- a general-purpose public API for invoking EXPRESS procedures or executable declarations unrelated to schema validation and ISO 10303-21 writing;
- operational resolution of external resources, digital-signature creation/verification, compressed archive transport, ECMAScript execution, or a claim that every syntactically recognized Edition 3 facility already has complete runtime semantics;
- implicit disk, network, package, or environment lookup for EXPRESS schemas not supplied as `.exp` AdditionalFiles;
- public reference/ID wrappers, lazy proxies, or resolver state attached to generated entities;
- automatic schema validation during property assignment, collection mutation, registration, removal, replacement-by-remove-and-add, or other intermediate editing operations;
- treating library-defined .NET mapping/documentation metadata as ISO-standard constructs or using reflection as the writer's schema source;
- public exposure of `ExchangeStructureSyntax`, a schema-free raw object graph, or a public raw/bound mode on `ExchangeStructure`;
- `TedToolkit.Assertions` runtime or generated-code dependencies.
- `TedToolkit.Annotations.Documentations` and custom reflection-readable EXPRESS constraint attributes.

Compatibility expectations:

- existing parser consumers remain source-compatible where current generated parser visibility permits;
- generated ANTLR files remain reproducible and are never edited manually;
- generated schema code references only the runtime validation contracts and no validation-engine or generator-only dependency;
- `ExchangeStructure.Validate()` exposes Step21 `ValidationResult` and immutable `ValidationFailure` values; generated validation callbacks are infrastructure, not a public rule-building API;
- generated schema code exposes one sealed singleton descriptor per EXPRESS schema through the runtime `SchemaDescriptor` contract; descriptor dispatch uses direct virtual/static calls and no discovery;
- public generated descriptor overrides consume only strong public ISO/runtime values and never receive a parser, binder, hydration, validation, or writing context object;
- public Part 21 reading and writing use `ExchangeStructure.Read(TextReader, IReadOnlyCollection<SchemaDescriptor>)`, `structure.Write(TextWriter)`, and `structure.WriteEntity(TextWriter, Entity)`; no separate public reader/writer facade or convenience overload changes these semantics;
- manual construction uses `ExchangeStructure(HeaderSection)` for temporarily unbound editing or `ExchangeStructure(HeaderSection, IReadOnlyCollection<SchemaDescriptor>)` for schema-bound editing; both expose the ISO header and a mutable data-section collection, and collection mutation does not validate;
- Native AOT acceptance publishes and runs the packed representative consumer for `win-x64`; this executable proof RID is not an exclusive support declaration;
- unsupported standard or schema features produce diagnostics and are not silently accepted as conforming;
- consumers never reference `ExchangeStructureSyntax`; public read either returns a complete validated `ExchangeStructure` or throws a stage-specific exception containing diagnostics/validation results.

## 🔄 Migration and rollback

- Migration: no persisted-data or public semantic-model migration is required because the current repository exposes only the internal parser/generator foundation. Existing consumers opt into the new schema-bound API by supplying `.exp` AdditionalFiles; generated parser types remain internal, and standard-conforming exchange structures require no format conversion.
- Compatibility gate: if delivery discovers that an existing public package contract, accepted exchange-structure input, or generated consumer source must break, stop and return the changed compatibility behavior to change design and renewed approval rather than treating it as a work-item detail.
- Rollback before release: revert the bounded target delivery artifacts as one unreleased capability while retaining the current parser baseline; no external operational rollback or data repair is required.
- Rollback after release: publish a correcting package version and keep the last conforming package available for consumers to pin. Exchange structures already emitted within the declared ISO capability remain standard data and are not rewritten merely because the package is rolled back. Do not retain or advertise a partially delivered schema-bound capability under the completed change's conformance claims.

Resulting constraints:

- ISO 10303-21 and the selected EXPRESS schema are the only sources of public domain semantics; C# conventions may improve representation but may not add, remove, or reinterpret a concept.
- Every public graph-registration operation requires an owned `DataSection`; omission is a compile-time API error, foreign-section rejection is atomic, and entities contain no structure, section, or occurrence-name back-reference.
- Parser, binder, hydration, diagnostic, metadata, and writer APIs are explicitly implementation infrastructure and do not appear as invented domain relationships or supertypes.
- The runtime is ISO- and schema-neutral; generated code depends on the runtime, never the reverse.
- Interfaces alone define EXPRESS inheritance and assignability; generated entity classes inherit only `Entity`, implement their own interface, and use CLR reference equality.
- Entity-valued properties expose the generated entity interface directly; the model owns instance names and performs two-phase hydration before read-boundary validation and publication.
- Generated entities are mutable and may be temporarily schema-invalid during explicit consumer editing; no intermediate mutation runs automatic schema validation.
- Step21 defines only the aggregate validation result, four-field failure (`Code`, string `Path`, `Message`, optional `SourceLocation`), non-public accumulation context, and stage-exception contracts required by its public boundaries. `SourceLocation` contains exactly `FilePath`, 1-based `Line`, and 1-based `Column`; it has no end span. Every failure invalidates the result; warnings remain diagnostics. EXPRESS remains the rule language; schema descriptors, executable generated validation, and XML documentation derive from the same bound IR.
- Step21 diagnostics use immutable `Step21Diagnostic` values containing `Code`, `Severity`, `Message`, and optional `SourceLocation`; `Step21DiagnosticSeverity` contains only `Information`, `Warning`, and `Error`.
- The public failure hierarchy is exact: `ExchangeStructureSyntaxException` and `ExchangeStructureBindingException` expose complete diagnostics; `ExchangeStructureReadValidationException` and `ExchangeStructureWriteValidationException` expose the complete `ValidationResult`; `ExchangeStructureCapabilityException` exposes the applicable diagnostics. Underlying `TextReader`/`TextWriter` I/O exceptions are not translated into schema failures.
- `EntityInstanceName` allocation is the smallest currently unused positive value. Add always requires an owned `DataSection`, returns the root name when allocating, is idempotent for an already registered identical pair, traverses new graphs root-first depth-first in `DirectReferences` order, and throws `InvalidOperationException` for a name/object conflict.
- `Remove(Entity)` and `Remove(EntityInstanceName)` return whether one registration existed, remove only that entity's identity and section membership, do not cascade or validate, and make the name reusable. No separate replacement API exists.
- No runtime validator discovery, registration container, rule-expression DSL, assembly scanning, expression compilation, or second validation source generator participates in schema validation.
- Writing is schema-aware and diagnostic; invalid/unsupported mappings are not guessed.
- Grammar behavior changes require clause-level evidence and focused fixtures.

## 🧭 Planned approach

The existing grammar/parser foundation is first reconciled production by production with the complete ISO 10303-21 Edition 3 clear-text WSN. The resulting visitor creates an internal immutable `ExchangeStructureSyntax` for every recognized standard syntactic form. This type is parser/binder infrastructure and is absent from public metadata. Advanced operational facilities may remain explicitly unsupported after parsing. The Analyzer reads `.exp` AdditionalFiles, converts ANTLR trees into a bound immutable schema IR, and reports syntax/semantic diagnostics. An incremental generator converts the IR through TedToolkit.RoslynHelper into public schema-derived entity/value types and a sealed descriptor, plus internal hydration helpers, direct validation/projection code, and XML documentation; it does not generate another public factory, reader, writer, resolver, registry, or context abstraction.

The Part 21 ANTLR visitor transforms a complete parse tree into internal `ExchangeStructureSyntax`, which preserves all valid multi-section and multi-schema declarations during binding but never crosses the public boundary. Typed binding resolves every data section's governing `SchemaName` against the explicitly supplied generated descriptors, then applies the applicable ISO schema-population and cross-schema reference rules. Delivery may stage a same-schema subset in an early work item only when the unsupported capability is explicit; final change completion permits no blanket multi-descriptor rejection. For each supported section, generated schema metadata binds syntax records: it first allocates and registers all generated entity objects in a new mutable `ExchangeStructure`, after which generated hydration code resolves raw occurrence names and assigns the actual objects to direct entity-valued properties. Only complete validation success publishes that structure. The writer validates it and uses its reference-identity reverse map to recover occurrence names before reversing each generated physical mapping into canonical ISO 10303-21 text.

The minimum public boundary is fixed as follows; generated descriptor implementations use direct statically reachable overrides and expose one sealed singleton descriptor per EXPRESS schema:

```csharp
public abstract class SchemaDescriptor
{

        AllocateEntityCore(entityNames);

        HydrateEntityCore(structure, value, components);

        ValidateCore(structure, entities);
    internal IReadOnlyList<Step21Diagnostic> GetCapabilityDiagnostics(
        ExchangeStructure structure) => GetCapabilityDiagnosticsCore(structure);
    internal IReadOnlyList<KeyValuePair<string, IReadOnlyList<ParameterValue>>> ProjectEntity(
        Entity value) => ProjectEntityCore(value);
    protected abstract Entity? AllocateEntityCore(IReadOnlyList<string> entityNames);
    protected abstract IReadOnlyList<Step21Diagnostic> HydrateEntityCore(
        ExchangeStructure structure,
        Entity value,
        IReadOnlyList<KeyValuePair<string, IReadOnlyList<ParameterValue>>> components);
    protected abstract ValidationResult ValidateCore(
        ExchangeStructure structure,
        IReadOnlyList<KeyValuePair<string, Entity>> entities);
    protected abstract IReadOnlyList<Step21Diagnostic> GetCapabilityDiagnosticsCore(
        ExchangeStructure structure);
    protected abstract IReadOnlyList<KeyValuePair<string, IReadOnlyList<ParameterValue>>>
        ProjectEntityCore(Entity value);
}

public sealed class ExchangeStructure
{
    public ExchangeStructure(HeaderSection header);
    public ExchangeStructure(HeaderSection header, IReadOnlyCollection<SchemaDescriptor> schemas);
    public HeaderSection Header { get; }
    public IList<DataSection> DataSections { get; }
    public EntityInstanceName Add(DataSection section, Entity value);
    public void Add(DataSection section, EntityInstanceName name, Entity value);
    public bool Remove(Entity value);
    public bool Remove(EntityInstanceName name);
    public ValidationResult Validate();

        IReadOnlyCollection<SchemaDescriptor> schemas);

    public void WriteEntity(TextWriter destination, Entity value);
```

`ParameterValue` is the strong schema-neutral ISO parameter union already required by the value system; it distinguishes scalar, recursively aggregated, typed/untyped, resolved-entity-reference, `$`, and `*` forms without exposing syntax nodes or using `object`. Descriptor hydration/projection receives an ordered BCL list of entity-component name/parameter-list pairs: simple instances contain one pair and complex instances contain all physical components in standard order. This avoids another public projection type while preserving component boundaries. Before descriptor hydration, runtime-internal binding resolves occurrence-reference parameters to registered `Entity` objects while preserving source diagnostics; before output, generated projection returns the same strong shape and the runtime maps entity objects back to structure-owned names. Runtime-internal non-virtual descriptor dispatch forwards directly to generated `protected abstract *Core` overrides. Capability diagnostics and every projection complete before the runtime writes any character. No public context, raw graph, parser state, resolver, accumulation API, nested type, or reader/writer facade is introduced. Each generated descriptor type exposes an `Instance` singleton. Syntax and binding failures throw `ExchangeStructureSyntaxException` and `ExchangeStructureBindingException`; invalid read publication and invalid write throw `ExchangeStructureReadValidationException` and `ExchangeStructureWriteValidationException`; a syntactically valid but unavailable advanced operation throws `ExchangeStructureCapabilityException`.

The EXPRESS ANTLR visitor separately transforms every syntactically valid ISO 10303-11 construct into source-located immutable IR, including functions, procedures, rules, `WHERE`, `UNIQUE`, and derived expressions. The Analyzer treats every `.exp` AdditionalFile in the current compilation as one closed input set, resolves `USE FROM` and `REFERENCE FROM` across declarations in that set, and reports source-located missing, duplicate, or conflicting schema diagnostics without probing undeclared disk or network locations. Name binding, inheritance closure, redeclaration analysis, physical mapping, and executable constraint compilation are later semantic stages and do not become grammar actions. Intermediate work items may report explicit unsupported-capability failures while the evaluator is incomplete, but no validation/write-reachable constraint may remain unevaluated when this change is complete. Unsupported executable declarations that are unrelated to validation or writing remain preserved in IR and outside the public execution API.

Mutable generated entities may be temporarily incomplete or schema-invalid during explicit consumer editing. The parser keeps `ExchangeStructureSyntax` and its hydration graph private until two-phase binding finishes and read-boundary validation succeeds. After hydration, `ExchangeStructure.Validate()` traverses every registered entity once by CLR reference identity, performs schema-neutral structure/reference checks, resolves each data section's governing `SchemaName` through the structure-owned generated-descriptor bindings, invokes statically generated schema validation, and returns one Step21 `ValidationResult`. Each immutable failure contains only `Code`, deterministic string `Path`, `Message`, and optional constraint `SourceLocation`. Any syntax, binding, or validation error causes the public read boundary to throw its applicable dedicated exception containing complete diagnostics or validation result; it returns no `ExchangeStructure` and exposes no syntax graph or generated entity from the failed attempt. Before consuming the supplied `TextReader`, the reader rejects duplicate `SchemaDescriptor.SchemaName` values with `ArgumentException`. Before emitting any character or byte, the writer completes both validation and supported-capability preflight; invalid models throw `ExchangeStructureWriteValidationException`, unsupported operations throw `ExchangeStructureCapabilityException`, and neither failure produces partial output. Property assignment, collection mutation, registration, removal, and replacement expressed as remove followed by Add perform no automatic schema validation. Explicit `Validate()` is side-effect-free and does not throw merely because its result is invalid. EXPRESS build failures remain Roslyn diagnostics and never deliberately escape by crashing the generator.

Generated property nullability follows EXPRESS rather than temporary editing state. Mandatory scalar and entity-reference properties are non-nullable and required for normal public construction; `OPTIONAL` properties alone are nullable. Setters run no validator and perform no schema check. C# nullable analysis therefore rejects ordinary missing mandatory assignments at compile time without creating a runtime validation boundary; a caller that deliberately circumvents the static contract, for example with the null-forgiving operator, receives the corresponding failure only from explicit validation or a Part 21 read/write boundary. Parser-only two-phase hydration may bypass public construction internally, but no typed graph is published before read-boundary validation succeeds.

The Runtime represents EXPRESS aggregates with four mutable schema-neutral categories. `ExpressList<T>` retains order and permits variable editing; `ExpressBag<T>` permits duplicates and treats order as non-semantic; `ExpressSet<T>` retains duplicate edit candidates so boundary validation can report them rather than silently discarding them; `ExpressArray<T>` retains its declared index domain and supports indexed slot assignment/unset rather than `Add`/`Remove`. Schema descriptors supply bounds, `OPTIONAL`, `UNIQUE`, and nested element semantics. Mutations do not run validation; invalid final states are aggregated by explicit or boundary validation.

Each generated entity implements a live, non-recursive `IEnumerable<Entity> DirectReferences` view through direct generated property access rather than reflection. It yields every physical entity-reference occurrence in write order, including entity values nested through aggregates or selects and repeated occurrences of the same object; it excludes nulls, derived attributes, and inverse attributes. The exchange structure composes these one-level views root-first and depth-first in physical occurrence order, uses CLR reference identity to terminate cycles and avoid duplicate registration, and assigns the smallest currently unused positive occurrence names only in the receiving structure. Every Add requires an explicit owned `DataSection` and re-enumerates the current live graph even when the root is already registered; the root keeps its name and section while newly reachable entities are registered normally. A section not present in the receiving structure throws `ArgumentException` before mutation. Newly encountered graph members join the selected section, while an already registered member keeps its existing section. Removal affects only the selected registration/membership, does not cascade, does not validate, and permits later reuse of its name. Re-enumeration observes current mutable values and does not cache stale references.

Generated XML documentation uses one deterministic caller-facing format derived from schema IR. Every generated type and member has a `<summary>`. Entity and defined-type remarks identify the EXPRESS schema and declaration. Attribute properties use `<value>` for CLR mutability/nullability and `<remarks>` for the normalized EXPRESS declaration, validation timing, and a table of stable constraint IDs with requirements. Each constraint ID is identical to the emitted `ValidationFailure.Code`. Generated schema descriptors link to the values and constraints they validate with `<see cref>`; read/write APIs document every stage-specific validation exception with `<exception>`. Examples use real generated/runtime APIs. XML text is escaped and normalized deterministically, does not claim that mutable intermediate values are valid, and remains semantically equivalent to validation behavior.

The current two-package direction is retained unless implementation evidence proves a third public package is necessary: the runtime owns public contracts; the Analyzer owns EXPRESS compilation and generation. Generator-time dependencies are packed alongside the Analyzer and never leak into generated code.

Alternatives rejected:

- generating directly from ANTLR contexts, because parsing does not resolve schema semantics or physical attribute mappings;
- reference wrappers or lazy proxies, because they violate the selected ordinary C# property shape; model-owned two-phase hydration preserves instance identity without exposing them;
- text-template generation or raw Roslyn SyntaxFactory, because TedToolkit.RoslynHelper is a hard constraint;
- domain-specific models, because they violate the approved product boundary.

Target delivery artifacts: production code, generated code, grammar only where normative evidence requires it, tests and fixtures, package/build configuration, and consumer/maintainer documentation.

ANTLR generation continues to use `-visitor -no-listener` in both platform scripts. The scripts gain checks that the expected parser, lexer, visitor, and base-visitor artifacts were regenerated and that listener artifacts were not emitted. Generated files remain derived artifacts and are never edited directly.
